# 主題三：如何從零到一建立全新的網頁頁面？ 🚀

當專案需要新增一個全新功能的獨立頁面（例如：會員註冊表單、服務常見問題 FAQ 頁面、專案活動專區）時，身為網站管理者，您需要從零規劃它與既有網站的導航連結、定義頁面間的互動層級，並產出符合品牌一致性的原型供團隊開發。

本單元介紹如何結合 **Google Stitch**（互動流程串接）與 **Claude Design**（精準組件生成），並在 **Figma** 中定稿建立全新網頁頁面的全流程協作。

---

## 💡 功能導向解決方案：全流程 AI 輔助協作

### 步驟 A：規劃頁面導覽與立體構造
在建立全新頁面之前，管理者應優先釐清其在既有網站架構中的位置：
1. **防止使用者迷路**：新頁面必須包含明確的定位元素（如麵包屑導航 Breadcrumbs 或常駐的全域導覽列 Global Navbar）。（參考：[掌握身在何處的四個元素](../垂直_水平_前後的立體構造/README.md#03-掌握身在何處的四個元素)）
2. **採用無縫式體驗**：針對局部更新或短流程的任務，優先評估是否採用彈出覆蓋式（Overlay Modal）或抽屜式（Slide-over Drawer），避免不必要的整頁跳轉。（參考：[無縫式介面](../無縫式介面/README.md)）

### 步驟 B：利用 Claude Design/Stitch 快速生成頁面骨架
1. **下達功能性 UI 生成指令**：向 Claude Design 或 Stitch 提供具體的新頁面功能與視覺規範，生成頁面骨架：
   ```text
   請為既有品牌網站建立一個全新的「常見問題與支援中心（FAQ）」頁面：
   1. 頂部導航：保留全域導覽列，下方提供麵包屑導航（首頁 > 客戶支援 > 常見問題）。
   2. 搜尋與分類：頂部設置醒目的關鍵字搜尋列，下方提供「帳號管理、帳單問題、系統操作」三項標籤切換（Tabs）。
   3. 主體排版：右側採手風琴摺疊面板（Accordion）展示問題清單，預設首題展開，其他收合。點擊時需有滑順展開動畫。
   4. 視覺風格：維持現代簡約風格，強調留白、文字階層分明與清晰的操作回饋（Hover/Active 狀態）。
   ```
2. **利用 Stitch 設定點擊流程**：在 Stitch 畫布上將既有舊頁面的按鈕（如 Header 上的「幫助中心」）與新生成頁面進行連線，確認整條 User Journey（使用者旅程）的點擊動線流暢無阻。

### 步驟 C：導入 Figma 定稿並進行元件化
1. **複用與擴充元件**：將生成的 UI 元素匯入 Figma，把按鈕、輸入框、色彩變數（Variables）與現有的設計系統（Design System）對齊，確保全站的 [一致性](../一致性/README.md)。
2. **啟用 Dev Mode 標註**：為工程師標註新元件的間距、排版約束（Auto-layout）與響應式斷點。

## 👥 與團隊的高效溝通指南

*   🗣️ **與設計師溝通（無縫體驗與元件複用）**：
    *   **討論焦點**：展示新頁面的原型動線。討論：「為了維持品牌一致性，我們可以直接複用既有的 Header、Footer 與 Button 元件嗎？」、「這個步驟表單的轉場動畫，應該如何在 Figma 中設定 Smart Animate 效果？」
    *   **交付物**：Stitch 的使用者旅程流程圖與 Claude Design 產出的新組件草案。
*   🗣️ **與工程師溝通（規格與技術實作）**：
    *   **討論焦點**：在 Figma 中啟用 Dev Mode 展示新頁面。對工程師說：「這是新網頁的規格。我們絕大多數按鈕與字級都沿用現有元件庫，僅新增了進度條與手風琴摺疊元件。請參考 Figma 標註實作前端轉場，避免使用者操作時產生全頁重新整理的跳轉感。」
    *   **交付物**：Figma Dev Mode 標註連結與新組件的互動行為說明。

## 📖 實作範例分享

以下提供包含「上課核心實戰」在內的三個具體實作範例，展示如何從零到一建立全新功能網頁並串接至既有系統：

### 🎓 上課實戰範例：既有品牌官網延伸 —— 從零整合「年度旗艦活動頁」導覽與無縫報名
*   **1. 情境設定**：
    *   **專案進度接續**：在主題一完成氛圍發想、主題二完成單頁內容與結構精修後，管理者現在需要將「2026 品牌年度體驗日」作為一個獨立的新功能頁面，正式整併至既有官網的架構體系中。
    *   **任務目標**：
        1. 在既有官網導航列中規劃活動入口（Navbar 新增活動標籤）。
        2. 在活動頁上實作核心轉換流程：**無縫式多步驟線上預約彈窗（Modal Overlay）**，讓訪客點擊按鈕後直接在原頁面跳出彈窗完成報名，無需全頁跳轉。
        3. **產出完整的互動原型與 Figma Dev Mode 規格，正式交付程式工程師進行前後端開發與 API 串接**。
    *   **核心挑戰**：必須讓 AI 產出的新頁面能無縫繼承官網既有的 Header 與 Footer，且彈窗內部的表單元件、驗證提示色與動效完全符合官網的設計系統規範。
*   **2. 實作方式（全站整合、無縫報名與交付工程師）**：
    1. **下達全站整合與無縫報名彈窗 Prompt**：
       在 Claude Design / Stitch 中輸入以下指令，整合全站架構並產生無縫報名流程：
       ```text
       請為既有品牌官網建立「2026 品牌年度體驗日」的完整獨立活動頁，並實作無縫報名彈窗互動：

       【全站架構與既有品牌規範】
       - 頂部導覽列（Global Navbar）：完全繼承既有官網導航樣式，但在右側醒目新增一顆帶有發光效果的標籤按鈕「🔥 2026 體驗日」，點擊即可導向此活動頁。
       - 麵包屑導航：活動頁頂部加入定位標示「官網首頁 > 最新活動 > 2026 品牌年度體驗日」。
       - 底部資訊（Footer）：完全沿用既有官網版權宣告、社群圖示與隱私權條款，維持全站一致性。

       【無縫式多步驟預約彈窗（Overlay Modal）】
       - 觸發行為：當使用者點擊頁面上的「搶先預約席位」按鈕時，背景產生深色半透明遮罩（backdrop-filter: blur(4px)），置中彈出寬度 520px 的卡片式表單。
       - 步驟 1【選擇場次與票種】：卡片單選（上午場論壇 / 下午場工作坊），並顯示剩餘名額提示標籤。
       - 步驟 2【報名人資訊】：包含姓名、手機號碼、Email 輸入框。輸入框採官網 12px 圓角與 Focus 琥珀橘外框高亮，具備即時格式防呆。
       - 步驟 3【確認送出】：訂單確認摘要與「確認送出」按鈕，點擊後於彈窗內原地切換為「預約成功！通知信已寄出」的綠色打勾動畫。
       ```
    2. **使用 Google Stitch 串接互動動線**：
       在 Stitch 畫布上將「官網首頁 -> 頂部活動標籤 -> 進入活動頁 -> 點擊搶先預約 -> 彈出報名 Modal -> 成功回饋卡片」拉出完整點擊動線，驗證整條 User Journey 的流暢性。
    3. **導入 Figma 並開啟 Dev Mode 交付程式**：
       將產出結果匯入 Figma，建立 Modal 的狀態變體（開啟/關閉/成功），開啟 **Dev Mode** 標註 Z-index（`z-index: 9999`）、轉場時間（`transition: all 0.3s ease-out`）與各欄位驗證正則規則。
*   **3. 溝通與交付成效（正式交給程式）**：
    *   **對設計師**：設計師認可無縫彈窗能有效降低跳出率，並將此「多步驟報名 Modal」收錄至全站共用元件庫（Design System）。
    *   **對工程師**：直接提供 Stitch 的互動動線與 Figma Dev Mode 標註。工程師獲得清晰的前端狀態機定義（場次選擇 -> 資料填寫 -> 成功畫面）與資料 Payload 格式，只需專注於串接報名後端 API 與簡訊通知，避免重複確認 UI 規格。

### 範例一：公務求職服務平台 —— 從零建立「無縫式求職會員線上註冊」多步驟頁面
*   **背景與痛點**：
    *   **現有網站**：[台灣就業通](https://www.taiwanjobs.gov.tw/)
    *   **目標**：規劃一個全新獨立的「求職者會員線上註冊」頁面。要求避免長表單帶來的心理抗拒感，具備即時密碼強度驗證與清晰的進度導引，達成流暢的無縫填寫體驗。
*   **AI 輔助開發過程**：
    1. **下達多步驟表單生成 Prompt**：在 Claude Design 中輸入完整的規格指令：
       ```text
       請為求職服務平台從零規劃一個全新的「求職會員線上註冊」頁面：
       - 頁面結構：置中卡片式設計（寬度 640px），背景為柔和淡灰。上方具備 3 步驟指示器（Step 1: 帳號設定、Step 2: 基本身分、Step 3: 求職意願）。
       - 即時驗證回饋：
         1. 密碼輸入框下方顯示「密碼強度條」（弱/中/強），並以紅、黃、綠顏色即時反饋。
         2. 身分證字號欄位輸入完畢後自動進行格式防呆，若錯誤則顯示紅色警示文字與圖示。
       - 導航與安全感：左上方放置「返回上一頁」連結與「已有帳號？直接登入」捷徑。底部提供明確的隱私權政策勾選框。
       - 操作按鈕：包含全寬「繼續下一步」主要按鈕，按鈕需具備 Disable（未填妥時）與 Active 狀態。
       ```
    2. **Stitch 流程串接**：在 Stitch 中將首頁頂部導覽列的「註冊」按鈕連線至此新頁面，設定點擊後為由右向左滑入的轉場動線。
    3. **Figma 定稿**：將生成介面導入 Figma，將主色調整為平台標準海藍色，並建立 Auto-layout 表單卡片。
*   **溝通成效**：
    *   **對設計師**：確認了 3 步驟表單的切換動效採用向左平移 200ms 的過渡方式，並將密碼強度條規格加入全站元件庫。
    *   **對工程師**：提早確認前端密碼規則的正則表達式（Regex），並規範表單資料在前端暫存（Session），直到最後一步才呼叫後端建立帳號 API。

### 範例二：衛生福利部健保署 —— 為既有服務擴充「智慧常見問題（FAQ）與互動摺疊面板」新頁面
*   **背景與痛點**：
    *   **現有網站**：[衛生福利部中央健康保險署](https://www.nhi.gov.tw/)
    *   **目標**：為減少民眾撥打客服電話的等待時間，需從零打造一個直覺、容易檢索的「常見問題 FAQ 與自助服務中心」全新頁面。
*   **AI 輔助開發過程**：
    1. **下達 FAQ 頁面生成 Prompt**：在 Claude Design 中輸入詳細的版面與互動生成指令：
       ```text
       請為全民健康保險服務平台設計一個全新的「常見問題與知識庫（FAQ）」網頁：
       - 頂部搜尋核心：中央放置大尺寸即時搜尋列（帶放大鏡圖示與一鍵清除「X」符號），搜尋列下方提供 4 個熱門關鍵字標籤：「健保卡補發」、「出國停保規定」、「投保金額試算」、「分期繳納申辦」。
       - 雙欄佈局規劃：
         1. 左側導覽列（25%）：垂直分類選單（Tab），包含「全部問題」、「承保資格」、「健保卡業務」、「就醫權益」、「醫療給付」。當前選取分類需有深藍底色與粗體標示。
         2. 右側主內容（75%）：採用手風琴面板（Accordion）條列常見問題。每個問題卡片右側附帶向下箭頭（Chevron），點擊展開時箭頭平滑旋轉 180 度，答案文字平滑展開，背景轉為淡藍色。
       - 底部輔助區塊：設置「找不到需要的解答？」支援卡片，包含「文字智能客服」與「免付費電話」兩顆快捷按鈕。
       ```
    2. **Stitch 動線串接**：在 Stitch 中將首頁 Footer 連結「常見問答」串接至此新頁面，並設定點擊熱門標籤時直接過濾右側 Accordion 內容。
    3. **Figma 交付與標註**：將 FAQ 頁面導入 Figma，建立展開/收合兩種變體（Variants），供團隊檢視互動邏輯。
*   **溝通成效**：
    *   **對設計師**：設計師認同「搜尋列 + 分類 Tab + Accordion」的雙欄結構能大幅降低視覺雜亂度，並快速完成了深色模式（Dark Mode）的適配。
    *   **對工程師**：工程師建議使用語意化的 HTML `<details>` 與 `<summary>` 標籤實作手風琴效果，兼顧 SEO、無障礙閱讀（A11y）與輕量動畫效能。
